# Таксономия закрытия заявок (HelpDesk + LLM)

## Две сущности в разборе

| Поле JSON LLM | Смысл | Пример |
|:--|:--|:--|
| `error_stage_ru` | **Где** в БП / разделе | «при проведении УПД» |
| `root_cause_ru` | **Почему** (техническое решение) | «асинхронность создания резервирований» |

Плюс `category` — код категории (NS, ORDER, auth, API …).

В скрытом комментарии одна строка:

`Контур: EDI / 1С · этап: … · причина: …`

Если `category` не сопоставилась с полями HD — код категории дописывается в эту же строку после «Контур: …».

## Поля IntraService (TypeId 1009)

| API-поле | UI (пример) | Что пишет чатбот |
|:--|:--|:--|
| `Field2229` | Тип закрытия (select) | Маппинг из `config/closure_taxonomy.json` → «Заказ», «API», «Предоставил инструкцию» … |
| `Field3061` | Ссылка на инструкцию (text) | Первая ссылка Confluence из `kb_refs`; если KB нет — текст `category` |
| `Field2711` | Внутренний справочник кодов (select) | Опционально, когда заполним `field2711_by_category` |

Настройка: `auto_fill_closure_fields: true` в `config/settings.default.json`. Поля обновляются при `--post` (вместе со скрытым комментарием).

## Категории 1С

Справочник в `config/closure_taxonomy.json` → `onec_categories` (NS, STOCK_NEGATIVE, EDI, UPD, …).  
Источник: корпус L1 + типовые кейсы; чат DeepSeek недоступен для автоимпорта — дополняйте JSON вручную.
