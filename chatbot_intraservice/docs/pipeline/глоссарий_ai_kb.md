# Справочник терминов: AI-KB и самообучение чатбота

Краткий глоссарий для ревьюеров черновиков и операторов Streamlit.  
Свод проекта: [Чатбот IntraService: пайплайн, AI-KB и настройки](https://confluence.dev.iek.ru/x/ONttBw).  
Схема: [Самообучение AI-KB (Corrective RAG)](https://confluence.dev.iek.ru/pages/viewpage.action?pageId=124641312).

---

## Зачем этот словарь

В интерфейсе и черновиках встречаются короткие пометки вроде «без PII email», `KB_INSERT`, `Promote`, `supplement`. Ниже — что они значат и **что реально произойдёт** при действиях в UI.

---

## Термины

| Термин | Что это |
|--------|---------|
| **AI-KB** | Контур самообучения: из закрытых заявок бот готовит черновики знаний для Confluence («Быстрые ответы»), человек ревьюит и публикует. |
| **Корпус** (`knowledge/lk\|bp\|1c\|crm/corpus.md`) | Локальный markdown-свод сценариев, который **вшивается в промпт** при разборе заявки. После Promote корпус пересобирается из «Быстрых ответов». |
| **Черновик** (`docs/черновики_статей/…`) | Файл + запись в `knowledge/learned/index.json`. Полный текст для человека: факты, урок, шаблон ответа. |
| **in_review** | Статус: ждёт решения человека (Promote или Отклонить). Уже может быть страница ревью в Confluence (`ai-kb-draft`). |
| **published** | После успешного Promote: текст из `KB_INSERT` попал в «Быстрые ответы». |
| **rejected** | Отклонено: в боевую KB **ничего** не пишется; причина учитывается при следующих learn. |
| **KB_INSERT** | Единственный фрагмент, который уходит в боевую KB при Promote. Маркеры: `<!-- KB_INSERT_START -->` … `<!-- KB_INSERT_END -->`. |
| **Promote** | Публикация: взять `KB_INSERT` → append на страницу «Быстрые ответы» (ЛК `124630014` / БП `124629661`) → обновить статус → пересобрать корпус. |
| **Отклонить (Reject)** | Не публиковать. Черновик → `rejected`, опционально причина для следующего обучения. |
| **new** | Режим: новая инструкция (новый код LK-NN / BP-NN). |
| **supplement** / **дополнение к LK-10** | Режим: не новая статья, а **добавка** к уже существующему блоку (например LK-10). На странице Confluence текст дописывается к блоку LK-10. |
| **Dedup / match_score** | Оценка похожести на уже известную статью/корпус. Высокий score → скорее supplement или skip, низкий → new. |
| **PII** | Personally Identifiable Information — персональные данные. В нашем контуре в первую очередь **email**, телефоны, ФИО из заявок. |
| **без PII email** | В черновике и в `KB_INSERT` **не должно быть** адресов вида `user@iek.ru` / партнёрских email. Скрипты вызывают `strip_emails`: адреса вырезаются. Раздел «Контекст заявки (без PII email)» — обезличенные факты для ревьюера, **не** для копирования в KB как есть. |
| **Быстрые ответы** | Боевые страницы WEBKB, откуда кормятся корпус и RAG. Не путать со страницей **ревью** черновика. |
| **Страница ревью** | Черновик в Confluence под папкой AI-KB (`ai-kb-draft`). Там правят текст; Promote читает локальный файл / sync, цель — «Быстрые ответы». |
| **gap** | «Дыра» в KB: при разборе не нашлось готового решения (`has_kb_solution=false`) или после закрытия compare показал, что человек ответил иначе. |
| **learn / pipeline_watch** | Автозапуск обучения по закрытым заявкам (28/29), если включён master `auto_learn_kb`. |
| **эвристика без LLM** | Fallback, когда gap-LLM не вернул JSON: черновик собран упрощённо — **часто плохой `KB_INSERT`**. Такие черновики править руками или отклонять. |

## Что происходит после Promote (пошагово)

Пример: `LK-10-SUP-694270` · дополнение к `LK-10` · контур ЛК.

1. Streamlit вызывает `scripts/sync_kb_after_review.py --task-id 694270`.
2. Из черновика извлекается **только** текст между `KB_INSERT_START/END`.
3. Этот текст **дописывается** к блоку **LK-10** на странице [Быстрые ответы · ЛК](https://confluence.dev.iek.ru/pages/viewpage.action?pageId=124630014) (pageId `124630014`).
4. Статус в `index.json` → `published`.
5. Пересборка локального корпуса ЛК (`build_*_corpus`), чтобы следующий разбор видел новое знание.
6. (Опционально) sync Open WebUI Knowledge.

**Не** происходит при Promote:

- весь черновик (урок, контекст, шаблон с артикулом из заявки) **не** копируется целиком;
- email из заявки в KB не должны попадать (если остались в `KB_INSERT` — это ошибка ревью);
- автоматического «исправления» плохого текста нет: в KB уйдёт **ровно то**, что в маркерах.

## PII / «без PII email» — подробно

| Можно в KB / корпус | Нельзя |
|---------------------|--------|
| Обезличенный сценарий («партнёр не видит остаток в ЛК, в 1С есть») | `ivanov@partner.ru`, `mrk@iek.ru` |
| Артикул как **пример типа** (осторожно) | Копировать ФИО, телефоны из HD |
| Шаги проверки (1С, склады контрагента, синхронизация) | «Напишите ваш email» в боевой инструкции |

Зачем: «Быстрые ответы» и корпус читают другие сотрудники и модели; персональные данные заявителя там не нужны и нарушают политику.

Раздел **«Контекст заявки (без PII email)»** в черновике — подсказка ревьюеру *о чём была заявка*. В Promote он **не** входит, если не продублирован внутри `KB_INSERT`.

## Чеклист перед Promote

1. Открыть превью **«Перед Promote»** в Streamlit: куда, какой блок, **точный текст вставки**.
2. Текст в `KB_INSERT` — это **знание для следующего исполнителя**, не фраза «мы проверим и устраним».
3. Нет email / телефонов / лишних номеров заявок.
4. Для **supplement**: текст логично дополняет LK-NN (не дублирует и не противоречит).
5. Если в черновике пометка «эвристика без LLM» или insert = вежливый отписочный ответ → **править** или **Отклонить**, не жать Promote.

## Пример плохого vs хорошего KB_INSERT

**Плохо** (отписка — бот не поймёт, к каким заявкам относится):

> Спасибо за сообщение. Мы проверим логику отображения остатков… Ожидайте обновление…

**Хорошо** (сценарий + поиск + шаги):

> **Сценарий:** В ЛК «Кол-во» = 0, в 1С по артикулу есть свободный/заблокированный остаток.  
> **Ключевые слова:** остатки, расхождение ЛК и 1С, inventory_display.  
> **Не путать с LK-10:** склады в каталоге (регистр «Склады контрагента»).  
> **Проверка исполнителя:** 1. Сверить 1С vs ЛК … 2. Синхронизация …

Полный шаблон: `docs/правила/формат_kb_insert.md`.

## Ошибка supplement (#694270)

Заявка про **остатки по артикулу** (LK≠1С) ошибочно попала как supplement к **LK-10** (склады в каталоге).  
После Promote на «Быстрые ответы» в конце страницы появился бессмысленный абзац — **удалите вручную** в Confluence и при необходимости добавьте отдельный блок **LK-12** (новый сценарий), не дописку к LK-10.
