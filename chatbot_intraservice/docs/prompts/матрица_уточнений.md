# Матрица уточнений: сервис × категория проблемы × цикл

Использовать, когда ответа KB нет / «Это не помогло» / пользователь создаёт заявку из чата.
**Не спрашивай то, что уже есть в диалоге.** За один ход — только вопросы текущего шага цикла.

## 0. Как устроен цикл

```
Шаг 0 (роутинг) → Шаг 1 (категория) → Шаг 2 (детали) → [Шаг 3 опционально] → черновик заявки
```

| Правило | Значение |
|:--|:--|
| Макс. шагов цикла | 1–3 (зависит от категории) |
| Вопросов за шаг | 1–3 |
| Макс. вопросов всего | ≤ 6 (если пользователь сам сократил — можно меньше) |
| Выход из цикла | обязательные поля заполнены **или** «создайте заявку как есть» |

### Шаг 0 — роутинг сервиса (всегда, если URL/контур неясен)

| Если тема | Спросить | Ответ → ServiceKey |
|:--|:--|:--|
| «ЛК», «кабинет», «партнёр», «API», «ключ», «заказы» без URL | **Какой контур?** `lk.iek.ru` (ЛК партнёра) **или** `bp.iek.ru` (бизнес-платформа / ЦКГ)? | lk / bp |
| «портал», «КП», «вход» без URL | Это `corp.iek.ru` / КП? | kp |
| «VPN», «диск», «сеть» | VPN / сетевой диск / иное? | vpn |
| «почта», «не приходит письмо» | Корпоративная почта Exchange? | mail |
| Иначе | Кратко: какой сервис и URL? | other |

После выбора контура — таблица категории ниже. Если ЛК vs bp неясен при API — **обязательно** Шаг 0.

## 2. Корпоративный портал (`kp` — corp.iek.ru)

### KP · AUTH — вход / сквозная авторизация

| Шаг | Вопросы (задавать блоком) |
|:--:|:--|
| 1 | 1) Офис / VPN / из дома? 2) Просит пароль/телефон или «сквозной» вход? 3) Текст ошибки (если есть) |
| 2 | 1) Когда началось (дата МСК)? 2) Логин (без пароля). 3) Воспроизводится сейчас? |

### KP · ACCESS — нет прав на раздел/сервис

| Шаг | Вопросы |
|:--:|:--|
| 1 | 1) Какой раздел/сервис на КП? 2) Раньше открывался? 3) Текст «отказано» / скрин |
| 2 | 1) ФИО и подразделение заявителя. 2) Кто владелец/согласующий (если известно) |

### KP · SMS_2FA — не приходит SMS / 2FA

| Шаг | Вопросы |
|:--:|:--|
| 1 | 1) Приходит ли SMS вообще? 2) Какой номер в профиле КП/AD (последние 4 цифры ок)? |
| 2 | 1) Домен УЗ: IEK / FEREX / LEDEL / иной? 2) Есть ли несколько УЗ? |

### KP · OTHER

| Шаг | Вопросы |
|:--:|:--|
| 1 | 1) Что именно не работает + URL. 2) Ошибка / скрин |
| 2 | 1) Когда началось. 2) Кого ещё затрагивает? |

## 3. ЛК партнёра (`lk` — lk.iek.ru)

> Если пользователь сказал «ЛК» или «API», но контур неясен — сначала: **lk.iek.ru или bp.iek.ru?**

### LK · AUTH — вход / учётная запись партнёра

| Шаг | Вопросы |
|:--:|:--|
| 1 | 1) Название партнёра. 2) Email сотрудника в ЛК. 3) Текст ошибки входа |
| 2 | 1) Когда началось. 2) Может ли другой сотрудник того же партнёра войти? |

### LK · ORDERS — заказы / корзина / оформление

| Шаг | Вопросы |
|:--:|:--|
| 1 | 1) Партнёр. 2) Раздел: новый заказ / история / конкретный №. 3) Что происходит (ошибка, зависание, нет кнопки) |
| 2 | 1) № заказа (если есть). 2) Артикулы / склад. 3) Время МСК |
| 3* | Скрин или точный текст ошибки (*если шагов 1–2 мало для заявки) |

### LK · NS_RESERVE — нестандарт / резервы

| Шаг | Вопросы |
|:--:|:--|
| 1 | 1) Партнёр. 2) НС или резерв? № заявки. 3) Что ожидаете vs что видите |
| 2 | 1) Дата создания. 2) Ошибка / статус «завис» |

### LK · API_LK — API каталога / интеграции ЛК (не ЦКГ)

| Шаг | Вопросы |
|:--:|:--|
| 1 | **Подтвердить:** API именно `lk.iek.ru` (не `bp.iek.ru`)? Метод/URL. HTTP-код |
| 2 | 1) Фрагмент ответа (без секретов). 2) Время запроса МСК. 3) Тип учётки (ключевая / пользователь) |
| 3* | Пример запроса (санитизированный) / Correlation-Id |

### LK · DOCS_UPD — документы / УПД / отгрузки

| Шаг | Вопросы |
|:--:|:--|
| 1 | 1) Партнёр. 2) № отгрузки / документа. 3) Что не так (нет файла, ошибка скачивания) |
| 2 | 1) Когда обнаружили. 2) Скрин |

### LK · OTHER

| Шаг | Вопросы |
|:--:|:--|
| 1 | Раздел ЛК + симптом |
| 2 | Партнёр + когда |

## 4. Бизнес-платформа (`bp` — bp.iek.ru / ЦКГ)

### BP · AUTH_KEY — ключи / доступ к ЦКГ

| Шаг | Вопросы |
|:--:|:--|
| 1 | 1) Бой `bp.iek.ru` (email+пароль) или тест `https://test-bp.iek.group/` (API-ключ)? 2) Чем входите — email/пароль или ключ? 3) Симптом |
| 2 | 1) Кто выдавал доступ. 2) Когда сломалось |

### BP · API_BP — API ЦКГ / ошибки вызовов

| Шаг | Вопросы |
|:--:|:--|
| 1 | 1) Подтвердить контур bp. 2) Endpoint. 3) Способ входа: email+пароль (бой) или API-ключ (только test-bp)? HTTP-код |
| 2 | 1) Время запроса МСК. 2) Частота (разово / массово). 3) Заказ/объект в ЦКГ (№) |
| 3* | Идемпотентность / повтор запроса / затронутые артикулы |

### BP · OTHER

| Шаг | Вопросы |
|:--:|:--|
| 1 | Раздел bp + симптом |
| 2 | Бой/тест + когда |

## 5. VPN / сеть / диски (`vpn`)

### VPN · CONNECT

| Шаг | Вопросы |
|:--:|:--|
| 1 | Текст/код ошибки VPN. Откуда подключаетесь (дом/офис/гостиница) |
| 2 | Клиент VPN (какой). Когда началось. IP 10.* появляется? (если уместно) |

### VPN · DISKS

| Шаг | Вопросы |
|:--:|:--|
| 1 | Путь/буква диска. Текст ошибки |
| 2 | VPN подключён? То же на другом ПК? |

## 6. Почта (`mail`)

### MAIL · DELIVERY — не приходит письмо

| Шаг | Вопросы |
|:--:|:--|
| 1 | Ящик получателя. Ожидаемые тема / отправитель (offers@, mailer@…) |
| 2 | Спам проверен? Когда должны были прийти. Есть ли у коллег? |

### MAIL · ACCESS — нет входа в почту

| Шаг | Вопросы |
|:--:|:--|
| 1 | Способ входа (Outlook / OWA). Текст ошибки |
| 2 | Когда началось. Сброс пароля уже пробовали? (без самого пароля) |

## 8. Стоп-условия (можно черновик заявки)

Достаточно, если заполнены:

1. **ServiceKey** (после роутинга lk vs bp при необходимости)
2. **Категория** (хотя бы по смыслу)
3. **Симптом** (текст ошибки или «что не так»)
4. **Заявитель** (email из сессии или явно)
5. **Контекст категории** — поля «Обязательно» из сводной таблицы  
   **или** пользователь сказал: «создайте заявку с тем, что есть»
