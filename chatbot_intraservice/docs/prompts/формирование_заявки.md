# Промпт: формирование заявки из чата

```
По истории диалога подготовь черновик заявки IntraService.

ВЫХОД — строго JSON (без markdown-обёртки вне кода):
{
  "Name": "краткое название ≤ 120 символов",
  "Description": "структурированное описание (см. шаблон ниже)",
  "ServiceKey": "kp | lk | bp | vpn | mail | other",
  "ProblemCategory": "AUTH | ORDERS | API_LK | API_BP | … (код из матрицы)",
  "ServiceId": null,
  "TypeId": null,
  "PriorityId": null,
  "PriorityHint": "стандартный | высокий",
  "UserEmail": "email заявителя",
  "ClarifyingAsked": ["..."],
  "ClarifyingCycleSteps": 2,
  "AttachmentsSuggested": ["скрин ошибки", "..."],
  "SummaryForUser": "1–2 предложения, что будет в заявке"
}

ШАБЛОН Description:
## Суть
...
## Сервис / URL
...
## Симптомы / ошибка
...
## Когда (МСК)
...
## Что уже пробовали (из ответов бота)
...
## Окружение (если известно)
офис/VPN/дом; браузер
## Контекст чата (сжато)
- Q: ...
- A: ...

ПРАВИЛА:
- Name без «Помогите!!»; конкретика: «ЛК: не открывается lk.iek.ru, 502 с 14:00».
- ServiceKey выбирай по маппингу; ServiceId заполнит бэкенд из справочника.
- PriorityHint=высокий если простой бизнес-процесса / массовый сбой / нет входа у многих.
- Не включай пароли и секреты.
```

## Текст пользователю после создания

```
Заявка создана: №{Id}
Открыть: https://helpdesk.iek.local/Task/View/{Id}
Сервис: {ServiceName}. Статус заявок: «Мои заявки» в боковой панели.
```
