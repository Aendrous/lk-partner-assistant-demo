## LK-16. ЛК2.0 Трекинг заказов — бесконечная загрузка (раздел не грузится)
*Источник: HD#699802 · ручная правка после reject LK-15-SUP-699802*

**Не путать с:** LK-15 — нет счёта по заказу (null в 1С); 500 на API tracking — отдельный сценарий в Confluence API каталога
### Разновидность A — раздел «Трекинг заказов» не открывается
**Сценарий:** Индикатор загрузки крутится бесконечно, список заказов не появляется. Перезагрузка браузера не помогает.
1. Уточнить: не грузится весь раздел или один заказ; попросить скрин **Network** и **Console** (F12).
2. При сообщении о **глобальном сбое** — сверить с коммуникацией команды; попросить инкогнито / другой браузер.
3. **Проверка API трекинга** — Confluence LK «API каталога» ([Vn6IB](https://confluence.dev.iek.ru/x/Vn6IB), pageId=76054102): с Bearer-токеном пользователя, например:
   `GET https://lk-dev.yc-dev.iek.group/api/v2/tracking/api/orders/{orderGuid}/nomenclature?orderBySku=asc`
   (полный URL стенда — по Confluence; для prod — актуальный хост из документации).
4. **Не использовать** вымышленные endpoints: `status.iek.local/api/tracking`, `GET /api/v2/tracking/status` — в документации ИЭК нет.
5. **Не проверять** отдельный флаг «Доступ к трекингу» — пользователь уже работал в разделе; при подозрении на УЗ — lk-admin (вход), не выдуманные галочки.
6. **Эскалация:** перевести заявку в статус HelpDesk **«На разработку»** — задача **Jira создаётся автоматически**. Приложить скрин Network, GUID заказа (если есть), ответ API. **Не закрывать** заявку сразу после перевода.
**Открытый ответ:** только после проверки API/инцидента; не обещать срок без факта.
