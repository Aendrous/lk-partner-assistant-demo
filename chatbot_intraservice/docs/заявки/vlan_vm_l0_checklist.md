# VLAN / VM: чеклист сети для L1 + L0

**Для кого:** ДИТ / сетевые админы при выдаче VM в отдельном VLAN.  
**Контекст:** на машине будут и фоновый бот HelpDesk (L1), и чат для диалога с сотрудниками (L0).

Отдельный VLAN — нормально. Важнее не «VLAN да/нет», а **кто может зайти на чат** и **куда VM ходит наружу**.

Спека L0: `docs/specs/L0_employee_chatbot.md`.  
Черновик заявки на деплой / сеть: `docs/заявки/дит_деплой_чатбота_n8n.md` (§5 firewall).

## Готовый ответ в чат ДИТ

> Отдельный VLAN для ботов — ок. На машине будет и фоновый разбор заявок HelpDesk, и чат для сотрудников.  
> Нужно: исходящий 443 на helpdesk.iek.local, llm.iek.local, confluence.dev.iek.ru; входящий 443 (HTTPS + DNS) с офиса/VPN на UI чата; порт операторской панели — только нам; 8765 (если n8n) — только с хоста n8n. Интернет с VLAN не обязателен.

## Исходящий доступ с VM (L1 и L0)

| Куда | Порт | Зачем |
|------|------|--------|
| `helpdesk.iek.local` | 443 | API заявок (watch L1 + создание заявки из L0) |
| `llm.iek.local` | 443 | ответы LLM |
| `confluence.dev.iek.ru` | 443 | WEBKB / prefetch |
| DNS + NTP корпсети | как принято | иначе не резолвятся имена |
| По сценарию позже | 443 | `adm.bp.iek.ru`, lk-admin, 1С — не для MVP L0 |

Интернет наружу **не обязателен**, если три хоста выше доступны из VLAN.

## Входящий доступ (отличие L0)

| Кто | Куда на VM | Зачем |
|-----|------------|--------|
| Подсети офиса + VPN ИЭК (сотрудники) | **443** reverse-proxy → L0-чат | диалог с пользователями |
| Узкий круг операторов | **8502** или отдельный path на 443 | панель Streamlit (настройки, AI-KB) |
| Только n8n (если будет) | **8765** с IP n8n | HTTP API watch; не из интернета |
| Интернет / чужие VLAN | закрыто | |

Попросить ДИТ:

1. DNS: например `chatbot-l0.iek.local` → IP VM.
2. Reverse-proxy (nginx/IIS): HTTPS 443 → приложение чата.
3. Firewall VLAN: allow ingress 443 from corp + VPN; deny other inbound.
4. Операторскую панель — path/basic-auth или только с VPN-группы операторов.

Голый `:8502` для всех сотрудников — только временный MVP; для прода — 443 + сертификат.

## На самой VM (не сеть)

- Учётка службы + autostart (Scheduler / systemd): watch L1 + UI.
- `.env` (права только службе): IntraService, `IEK_LLM_TOKEN`, `CONFLUENCE_PAT`.
- L0 создание заявки от сотрудника: **SSO / UserEmail** (часть 2 спеки) — иначе заявки от сервисной УЗ.
- Ресурсы: 2 vCPU, 4–8 GB RAM, ~20 GB диск (+ `pipeline/runs/`).

## Чего VLAN не решает

- `selectservice` в IntraService **не** запускает бота без доработки вендора — нужна ссылка на L0.
- Изоляция VLAN ≠ авторизация в чате: без логина любой с доступом к URL может писать боту.
