Связанные страницы: [пайплайн и настройки](https://confluence.dev.iek.ru/x/ONttBw) · [самообучение AI-KB](https://confluence.dev.iek.ru/pages/viewpage.action?pageId=124641312) · [схема 1 линии](https://confluence.dev.iek.ru/pages/viewpage.action?pageId=124630073).

## 1. Где настраивается

| Способ | Для кого | Что меняет |
|---|---|---|
| **Streamlit** (`app.py`, порт 8502) | Оператор / владелец продукта | Галочки контуров (ЛК/БП/CRM/1С…), watch, обучение, подчинение дублей → `config/settings.local.json` |
| **JSON defaults** | Разработчик | Безопасные значения по умолчанию → `config/settings.default.json` |
| **Секреты** | Админ | Cookie/логины для adm.bp, lk-admin, 1С → `.env` (не в git) |
| **n8n / Task Scheduler** | ДИТ | Расписание watch-скриптов или HTTP `n8n_http_server :8765` |

Принцип: **всё опционально** — каждая «фича» включается отдельным флагом; без секретов бот всё равно пишет разбор, но без live-проверок внешних систем.

## 2. Реализовано: список возможностей

### 2.1 Скрытый разбор заявки для исполнителя

**Что делает:** LLM читает описание, переписку, вложения (скрин/PDF/DOC) и пишет **скрытый комментарий**: суть, факты, шаги по KB, черновик открытого ответа.

| Настройка | По умолчанию | Как отключить |
|---|---|---|
| `auto_post_comment` | `false` | В UI снять «Автопост» или в local `false` |
| `contour_enabled.<контур>.comment` | ЛК/БП/1С — on в defaults; CRM — on в пилоте | Галочка «Разбор» у контура в Streamlit |
| `public_reply_only_if_kb` | `true` | Открытый ответ только если есть решение в KB |

**Контуры:** ЛК (731/732), БП (827/833), CRM (29), EDI/1С (69), почта, прочее — отдельно для разбора, watch и обучения.

---

### 2.2 Автозаполнение полей закрытия (код закрытия, ссылка на инструкцию)

**Что делает:** при публикации разбора (`--post`) бот заполняет поля HelpDesk:

| Поле HD | Смысл | Откуда берётся |
|---|---|---|
| **Field2229** | Тип закрытия (заказ, API, инструкция…) | Код категории LLM → маппинг в `closure_taxonomy.json` |
| **Field3061** | Ссылка на инструкцию | Первая ссылка Confluence из ответа LLM; если KB нет — текст категории |
| Строка в комментарии | «Контур · этап · причина» | `error_stage_ru` + `root_cause_ru` от LLM |

| Настройка | По умолчанию |
|---|---|
| `auto_fill_closure_fields` | **`true`** |

**Отключить:** `auto_fill_closure_fields: false` в settings.

**Частично:** Field2711 (внутренний справочник кодов) — структура есть, автозаполнение **пока не настроено** (пустой маппинг).

Документация: `docs/pipeline/таксономия_закрытия.md`.

---

### 2.3 Проверка учётки в БП (adm.bp.iek.ru)

**Что делает:** по email из заявки ищет клиента в админке БП → одна строка в разборе: найден/не найден, тип (LEGAL/PERSONAL), ИНН, заблокирован ли.

**Когда вызывается:** контур БП (ServiceId 827/833), упоминание bp.iek.ru / IEK ID; **не** вызывается для чистых ЛК-заказов.

**Как включить live-проверку:** в `.env` задать `BP_ADM_COOKIE` (сессия Keycloak). Без cookie — строка «нужен BP_ADM_COOKIE» + ссылка для ручной проверки.

Модуль: `src/bp_adm.py`.

---

### 2.4 Проверка учётки в ЛК (lk-admin)

**Что делает:** поиск в Bitrix admin (`lk.iek.ru/bitrix/admin/user_admin.php`) → email, дата последнего входа.

**Когда вызывается:** вопросы доступа/авторизации ЛК, API каталога; **не** для заказов/резервов/ТТН без темы доступа.

**Как включить:** `LK_ADMIN_COOKIE` или логин `LK_USER` / `LK_PASSWORD` в `.env`.

Модуль: `src/lk_adm.py`.

---

### 2.5 Проверка номера заказа в 1С

**Что делает (сейчас):** если в тексте есть номер заказа и тема про резерв/заказ — запрос в 1С: включена ли галка **«Резервировать товары в пути»** у `Документ.ЗаказПокупателя`.

**Транспорт:** OData (`1C_BASE_URL`) или COM (`1C_CONN` + `V83.COMConnector`). Fallback — ручные override в `knowledge/learned/1c_overrides.json`.

**Scope:** `onec_analyze_scope` — `"all"` (по умолчанию) разбирает весь контур Солярис, `"logistics_tn"` — только ТН ОП-2765. Вне зависимости от scope предразбор **не** выполняется для заявок «запрос на изменение» (TypeId 1010) и уже «в работе» (StatusId 27).

**Не реализовано:** полная сверка заказа (статусы НС, остатки, цепочка документов) — только флаг резерва в пути.

Модуль: `src/onec_client.py`.

### 2.6 Связанные заявки и подчинение дублей (ParentId)

**Два уровня:**

1. **Справка** — строки «Связанные / Похожие» в комментарии (поиск по заказу, счёту, GUID, тендеру CRM).
2. **Подчинение** — поздняя заявка → `ParentId` к более ранней; инициатор ранней → наблюдатель.

| Настройка | По умолчанию | Смысл |
|---|---|---|
| `link_related_on_post` | `true` | Включить логику при `--post` |
| `link_related_same_day_only` | `true` | Только заявки того же дня |
| `link_related_same_service` | `true` | Тот же ServiceId |
| `link_related_open_status_ids` | 31,38,121,27,46,120 | Только открытые статусы |
| `link_related_by_contour.crm` | **`false`** | CRM не линкуем (слишком много ложных совпадений по GUID) |
| `add_parent_creator_as_observer` | `true` | Добавить автора ранней заявки в наблюдатели |

**Отключить подчинение:** снять галочку «Подчинение» у контура в Streamlit или `link_related_on_post: false`.

### 2.7 Watch-роботы (фоновые сценарии)

| Сценарий | Триггер | Действие | Флаг |
|---|---|---|---|
| **Новые заявки** | Статусы 31/38/121 | Разбор + скрытый комментарий | `watch_new_enabled` |
| **Ответ заявителя** | Статусы 46/120 | «Спасибо/можно закрывать» → **29** + скрытый; «проблема не решена» → **38**; уточняющий вопрос — статус не меняем; nudge исполнителя → **120**; CRM-статусы отдельно | `watch_user_reply_auto_close` / `watch_user_reply_crm_status_changes` |
| **Просрочка** | Маркер «До просрочки» | +1 день deadline, публичный ответ при KB | `watch_overdue_enabled` |
| **Закрытие → learn** | Статусы 28/29 | Черновик AI-KB если gap | `auto_learn_kb` + `auto_learn_on_close` |

Контуры: `contour_enabled.<контур>.watch` — отдельно для ЛК/БП/CRM/1С.

Оркестрация: Windows Task Scheduler, **n8n** (`n8n.iek.local`) или HTTP API на ноутбуке.

#### 2.7.1 Ответ заявителя (`watch_user_reply`) — зачем и как

**Зачем отслеживать:** когда заявка уже в «Ожидании ответа» (46) или «…с автозакрытием» (120), повторный скрытый разбор исполнителю не нужен. Полезные сигналы — подтверждение решения, доп. вопрос заявителя, либо повторный опрос актуальности от исполнителя.

**Что делает бот (если `watch_user_reply_auto_close: true` / `watch_user_reply_reopen_enabled: true`):**

1. Находит **новый комментарий заявителя** (не исполнителя, не бота).
2. **«Спасибо / помогло / можно закрывать»** → статус **29** «Выполнена» + **скрытый** комментарий «Пользователь подтвердил решение» (+ правило).
3. **Уточнение, «не помогло», доп. вопрос** (из 46 или 120) → статус **38** «Передано исполнителю» + **скрытый** комментарий с правилом.
4. Если нового ответа заявителя нет, но в **46** есть **повторный вопрос исполнителя** («требуется ли ещё что-то / актуальна ли заявка») спустя ≥`watch_user_reply_relevance_nudge_hours` (по умолчанию 24 ч) после первого ответа исполнителя → статус **120** + **скрытый** комментарий с правилом.

**Что не триггерит:** нейтральные письма без сигнала; длинные техписьма без явного «не помогло» / уточнения.

| Настройка | По умолчанию | Смысл |
|---|---|---|
| `watch_user_reply_enabled` | `true` | Включить watch |
| `watch_user_reply_auto_close` | `true` | Подтверждение → 29; nudge → 120 |
| `watch_user_reply_reopen_enabled` | `true` | Уточнение / не помогло → 38 из 46/120 |
| `watch_user_reply_autoclose_days` | `2` | Срок в тексте скрытого комментария при nudge (закрытие — правила HD) |
| `watch_user_reply_relevance_nudge_hours` | `20` | Минимум часов после первого ответа исполнителя до nudge→120 (≈сутки / утро след. дня) |
| `watch_user_reply_status_ids` | 46, 120 | Из каких статусов смотреть |
| `watch_user_reply_max_age_hours` | 72 | Игнорировать старые комментарии |

См. также журнал исправлений: [Баги и исправления чатбота](https://confluence.dev.iek.ru/pages/viewpage.action?pageId=124642389) (`docs/bugs_and_fixes.md`).

### 2.8 Самообучение AI-KB и автосоздание черновиков

**Цепочка (Corrective RAG):**

```
Закрытая заявка (28/29) → нет готового ответа в KB
  → сравнение ответа бота и исполнителя
  → LLM: новая статья / дополнение / пропуск
  → черновик в docs/черновики_статей/
  → ревью оператором (Streamlit)
  → Promote в «Быстрые ответы» Confluence
```

| Настройка | По умолчанию | Смысл |
|---|---|---|
| `auto_learn_kb` | **`false`** | Мастер-выключатель обучения |
| `auto_learn_on_close` | `true` | Learn при закрытии (если мастер on) |
| `auto_learn_on_analyze` | `false` | Learn сразу при разборе (обычно off) |
| `auto_push_confluence_draft` | `false` | Сразу пушить черновик в Confluence на ревью |
| `skip_if_kb_found` | `true` | Не учить, если KB уже закрыла вопрос |
| `semantic_dedup_enabled` | `true` | Не плодить дубли черновиков |

**Включить пилот:** в Streamlit — «Обучение KB» у нужного контура + `auto_learn_kb: true` в local.

**Promote (куда попадают статьи после ревью):**

| Контур | Страница Confluence |
|--------|---------------------|
| ЛК | [Быстрые ответы WEB: ЛК](https://confluence.dev.iek.ru/pages/viewpage.action?pageId=124630014) |
| БП | [Быстрые ответы WEB: БП](https://confluence.dev.iek.ru/pages/viewpage.action?pageId=124629661) |
| CRM | [Быстрые ответы: CRM РФ](https://confluence.dev.iek.ru/pages/viewpage.action?pageId=124642256) (CRMRF) |
| 1С Солярис | [Быстрые ответы: 1С Солярис](https://confluence.dev.iek.ru/pages/viewpage.action?pageId=124642091) (1C) |
| 1С ТН ОП-2765 | [Быстрые ответы: ТН](https://confluence.dev.iek.ru/pages/viewpage.action?pageId=124642131) (1C) |

Карта: `docs/confluence/kb_assistant_pages.json`.

| Идея | Зачем | Что нужно |

### 4.3 Средний горизонт (Iteration 2–3)

| Идея | Зачем | Статус |
|------|-------|--------|
| **Кластеризация похожих тикетов** | 3+ одинаковых кейса → одна статья KB | Backlog (`IDEA_RAG_LEARNING.md`) |
| **L0 — чат, встречающий сотрудника** | Вопрос → KB или заявка с правильным сервисом | Спека готова, кода нет |
| **Качество corpus** | Симптом / не путать / проверка / ответ | В работе (Iteration 2) |
| **Langfuse / observability LLM** | Метрики качества разбора | Backlog |
| **События IntraService вместо cron** | Сейчас бот **опрашивает** HD по расписанию (watch_new каждые N минут). Идея: IntraService при смене статуса **сам шлёт HTTP-запрос** на наш сервер — разбор сразу, без задержки опроса. **Не реализовано** — нужен endpoint в HD или middleware. | Backlog |

## 5. Рекомендуемый порядок включения (пилот)

1. **Watch new** на ЛК/БП — без автопоста, ручной `--post` на выборке заявок.
2. **auto_post_comment** — после приемки качества разбора.
3. **auto_fill_closure_fields** — уже on; проверить маппинг категорий на отчётах HD.
4. **Секреты adm/lk** — для заявок по доступу (cookie от владельца админок).
5. **auto_learn_kb** — на одном контуре (например ЛК), ревью в Streamlit.
6. **CRM** (ServiceId 29) и **1С** (69) — включены в пилоте; Promote в CRMRF / 1C.
