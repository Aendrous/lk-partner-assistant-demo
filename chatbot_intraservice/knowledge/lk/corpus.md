## LK-06. В ЛК нельзя поставить галочку / подтвердить «в пути»

**Проблема:** партнёр пишет «не даёт поставить галочку» по резервам в пути; кнопка/галка в ЛК неактивна.

**Проверка 1С:** заказ покупателя → галка **«Резервировать товары в пути»**.

**Если галка в 1С стоит:** товар уже резервируется в пути на стороне 1С. **Подтверждение в ЛК не требуется.** Галка в ЛК может отсутствовать именно поэтому. **Дефект UX:** если в карточке заказа нет явной подписи статуса — партнёр думает, что «сломалось»; нужна доработка отображения «уже зарезервировано / подтверждение не требуется».

**Если галка в 1С снята:** смотреть другие причины неактивной кнопки: заказная продукция `isCustomized` (WEBKB 76054339), комплект, согласование заказа (WEBKB 72222277).

## LK-10. В ЛК пропали / не отображаются склады в каталоге

**Проблема:** партнёр в ЛК видит меньше складов (или не видит нужные: Щербинка, Чехов, Екатеринбург и т.п.); кнопка «настройка» складов не помогает.

**Не путать с:** остатки по API / выгрузка остатков; «видит ещё N шт на складе» в письме об отгрузке; инструкция создания пользователя ЛК.

**Решение:** список доступных складов партнёра в каталоге ЛК берётся из 1С, регистр **«Склады контрагента»**. Включает/отключает МРК (или по согласованию с МРК). Исполнитель сверяет контрагента в 1С с перечнем из заявки и отвечает, какие склады есть в регистре.

**Открытый ответ (шаблон):** Доступные склады для партнёра настраиваются в 1С в регистре «Склады контрагента» при содействии МРК. Сейчас в регистре: … (указать по факту проверки). Склады вне регистра в каталоге ЛК не отображаются.

**Смежные статьи:**  
https://confluence.dev.iek.ru/pages/viewpage.action?pageId=124630014  

**Образец HD:** 697812.

## LK-12. Остатки в ЛК ≠ 1С (расхождение и «количество на блоке»)

**Источник:** HD#694270 · https://helpdesk.iek.local/Task/View/694270

**Ключевые слова:** остатки, расхождение ЛК и 1С, кол-во 0, количество на блоке, поверка, каталог 3.0, inventory_display, заблокированный остаток, артикул.

**Не путать с LK-10:** список складов в каталоге (регистр «Склады контрагента»), не остаток по артикулу.

### Разновидность A — общее расхождение остатков

**Сценарий:** в ЛК поле «Кол-во» = 0 или неактивно; в 1С по артикулу есть свободный и/или заблокированный остаток (новая версия ЛК vs старая).

1. Сверить в 1С: свободный vs заблокированный остаток по артикулу и складу.
2. Проверить синхронизацию остатков ЛК ↔ 1С (не только «Склады контрагента»).
3. Исключить заказную продукцию, кратность, блокировки (LK-06, WEBKB).

### Разновидность B — «количество на блоке» (поверка)

**Сценарий:** артикул с **количеством на блоке** (приборы на поверку после заказа). В каталоге **ЛК 2.0** в скобках показывалось кол-во на блоке; в **каталоге 3.0** — нет, хотя товар на складе есть. Заказчик должен видеть наличие: поверка добавляет время, но остаток отображать нужно.

1. Уточнить признак «на блоке» / поверка; сравнить отображение 2.0 vs 3.0.
2. Сверить остаток в 1С (в т.ч. заблокированный) с карточкой в ЛК 3.0.
3. При баге UX/синхронизации — эскалация WEB/1С с артикулом и скринами (без email в KB).

**Открытый ответ:** только после факта проверки; не обещать «ожидайте обновление» без результата.

## LK-11. API каталога ЛК — регистрация и письмо mailer@iek.ru

**Проблема:** партнёр регистрируется на https://lk.iek.ru/products/api/join/ или просит доступ к **API каталога** (синхронизация каталога), но не получает письмо с логином/паролем от **mailer@iek.ru** (спам, задержка, неверный email).

**Не путать с:** API-ключ на **bp.iek.ru** (Бизнес-платформа, profile#api-keys, username=ticket) — это другой контур (HelpDesk 833 / BP-06).

**Контур:** ЛК (ServiceId 732). Учётка «внешний пользователь API» создаётся поддержкой WEB в Bitrix (`lk-admin`).

**Проверка исполнителя:**
1. `lk-admin`: user_admin.php?find=<email>&find_type=email — есть ли учётка; при доступе — дата последнего входа (если **никогда не входил** → сценарий «нет письма / сброс пароля»).
2. Сверить email в заявке с тем, что указан при регистрации на join/.
3. Попросить проверить спам и папку «Рассылки» для mailer@iek.ru.

**Если учётка есть, партнёр не входил:** открытый ответ — сброс через IEK ID: https://iekid-profile.iek.ru/forgot-password (P-00/P-16). Пароль в чат не запрашивать.

**Если учётки нет:** оформить/дозавести внешнего пользователя API по процессу WEB; после создания пароль уходит с mailer@iek.ru.

**Открытый ответ (шаблон, нет письма):**
Доступ к API каталога ЛК оформляется через https://lk.iek.ru/products/api/join/ . Данные для входа приходят с адреса mailer@iek.ru — проверьте папку «Спам» и «Рассылки». Если письма нет — восстановите пароль через IEK ID: https://iekid-profile.iek.ru/forgot-password (логин — email из заявки). Это доступ к API каталога ЛК, не API-ключ bp.iek.ru.

**Смежные:** P-00 вход в ЛК, P-16 профиль; разбор заявки (API каталога vs bp).

**Образцы HD:** 696430 (регистрация join), 697972 (не пришло письмо mailer@iek.ru).

## LK-16. ЛК2.0 Трекинг заказов — бесконечная загрузка (раздел не грузится)

**Сценарий:** В разделе «Трекинг заказов» ЛК крутится индикатор, данные не появляются. Перезагрузка не помогает.

**Ключевые слова:** трекинг, бесконечная загрузка, ЛК2.0, tracking api, orders, nomenclature

**Не путать с:** LK-15 — нет счёта по заказу (null в 1С); отдельный кейс 500 на API tracking.

**Проверка исполнителя:**
1. Уточнить: не грузится весь раздел или один заказ; попросить скрин Network/Console (F12).
2. При массовом сбое — сверить с коммуникацией команды (инцидент); инкогнито / другой браузер.
3. **API трекинга** — документация Confluence LK «API каталога» ([Vn6IB](https://confluence.dev.iek.ru/x/Vn6IB), pageId=76054102): проверка с Bearer-токеном пользователя, например  
   `GET …/api/v2/tracking/api/orders/{orderGuid}/nomenclature?orderBySku=asc`  
   (стенд и полный URL — по Confluence; не использовать вымышленные `status.iek.local` / `/tracking/status`).
4. Отдельный флаг «Доступ к трекингу» в админке **не диагностируют** — пользователь уже в ЛК; при УЗ — lk-admin (вход), не выдуманные галочки.
5. **Эскалация:** статус HelpDesk **«На разработку»** → задача **Jira создаётся автоматически**; приложить скрин Network, GUID заказа, ответ API. **Не закрывать** заявку сразу после перевода.

**Смежные:** LK-15 (нет счёта); Confluence API каталога 76054102.

**Образец HD:** 699802.
