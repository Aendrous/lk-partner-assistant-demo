# Decision log — разработка через ИИ

> Долгоживущий лог ключевых решений по подходу к ИИ‑разработке.
> Сессионные решения — в `docs/pipeline/решения.md`.

## 2026-09-07 — Подход к работе через слабые модели

- **Решение:** ввести `.clinerules/rules.md`, который описывает план‑ориентированный
  подход, микрозадачи и fallback на `gpt-oss-120b`, если primary‑модель
  (`deepseek-v4-flash` / `luna-7b`) «слишком длинная» или пустая.
- **Мотив:** на слабых моделях «спагетти‑промпты» дают плохой diff и растягивают
  контекст до предела. Дробление + микровалидация даёт стабильный результат
  даже на `luna-7b`.
- **Последствия:**
  - контекст для модели дробим до 3–4k токенов;
  - one LLM‑call = one editor‑edit / one read / one test;
  - перед правкой обязателен `read_files` нужного диапазона;
  - после правки — `python -m pytest -q`.
- **Связанные:** AGENTS.md (правила кодирования), docs/pipeline/решения.md.

- **Зачем:** быстрая диагностика fallback и понятная история для релизов.
